# 数据清洗规则清单

> T3 阶段 3 产出，对应《数据清洗基本流程-操作SOP》第 5 节。
> **每条规则都挂在 [02_issues.csv](02_issues.csv) 的实测问题编号上**，或挂在 SOP 明文要求的统一动作上——
> 没有依据的规则不写。执行见 `bigdata/spark/cleaning.py`，校验见 `validation.py`。

## 总原则（SOP 第 5 节）

- 能按确定规则修正的，自动修正并**记录旧值新值**
- 无法确定但仍有价值的，**保留并标记待核**
- 真实异常不因数值极端而自动删除
- **删除是最后手段**，必须记录数量、原因和样例
- 关键字段（业务主键、金额、目标变量）不套用通用规则

## R002 · 类型转换，失败记录不静默丢弃

| 项 | 内容 |
| --- | --- |
| 作用对象 | **全部 11 张 DWD 表、94 个需转类型的列**，与 R003 的时间/日期列合并判定。转哪些列由 [`bigdata/spark/dwd_schema.py`](../spark/dwd_schema.py) 的 Schema 契约声明，**不在代码里各写各的** |
| 实现方式 | `cleaning.py` 的 `cast_with_capture()` 统一承担：先把转换结果写影子列 `_col`，比对完再替换回来。**不能原地 `withColumn`**——那会盖掉原值，待核清单就拿不到「原始值」，等于没查。转换后由 `enforce()` 按契约排列列序并断言类型 |
| 检测条件 | 转换为 int/double 后为 NULL，但原值非 NULL |
| 处理动作 | 主体转换为强类型；**失败行整行写入待核清单**，不置空 |
| 处理依据 | SOP 6.2「类型转换失败的值不要静默变为空值，应输出失败记录与原始值供复核」 |
| 影响评估 | 探查显示各列取值规整，预计 0 行失败 |
| 异常去向 | 按表分文件 `pending/type_cast_failed_<表名>.json`，**11 份全部落地，空清单也留文件** |
| 验证方式 | `validation.py` 每张表三条断言：① 列序与类型符合契约；② 契约声明非空的列确无 NULL；③ 待核清单存在且为 0 行，且转换列非空数在 ODS 与 DWD 间**逐列一致**。③ 的后半句才是真正的静默置空探测器——清单为空但非空数掉了，说明捕获逻辑自己漏了。实测 11 表 132 列全部符合，失败合计 0 行 |

**两个工作簿的取值口径不同，是有意的**：
