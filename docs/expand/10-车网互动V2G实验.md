## 3 业务流与数据流

### 3.1 实验授权

```text
用户进入明确标注“纯模拟”的 V2G 实验页
  -> 阅读实验说明并开启授权
  -> 设置最低保留 SOC、预计离场时间和授权有效期
  -> 服务端校验用户、虚拟车辆能力和参数
  -> 保存版本化 enrollment 与审计日志
```

授权不等于接受某次调度。每次实验调度仍需单独邀请和接受；用户暂停、撤销或授权过期后不得创建新计划。

### 3.2 计划、邀请与开始

```text
固定预测/实际负荷超过实验阈值
  -> V2GPlanner 计算目标削峰功率
  -> 筛选已授权、在线、支持双向、无普通充电会话的虚拟车辆
  -> 服务端计算可用能量和最大输出功率
  -> 生成 DRAFT 计划和 OFFERED 会话
  -> 用户接受邀请
  -> 服务端再次检查授权版本、SOC、离场时间、设备连接和资源互斥
  -> 通过设备命令服务下发 SET_BIDIRECTIONAL_POWER(direction=EXPORT)
  -> 模拟器 ACK/RESULT 后进入实验输出阶段
```

模型只能建议候选车辆和功率；服务端必须重新执行全部安全与互斥校验。模拟器无权创建普通订单或修改钱包。

### 3.3 遥测、停止与模拟补偿

```text
模拟器上报 V2G_TELEMETRY（方向、功率、累计输出 Wh、SOC）
  -> 服务端校验单调性、新鲜度和会话关联
  -> 更新 V2G 会话与站点模拟净负荷
  -> 每个时间片重新检查最低 SOC、授权、心跳和离场时间

峰值结束 / 用户撤销 / SOC 到下限 / 设备掉线
  -> 服务端下发 direction=IDLE、powerW=0
  -> 收到最终输出 Wh 或按安全策略终止
  -> 生成唯一的模拟补偿账本记录
  -> 会话 SETTLED，资源锁释放
```

模拟补偿可以使用“模拟分”为单位；即使页面以人民币格式展示，也必须标记“模拟金额”，并与正式钱包及营收查询物理隔离。

## 4 状态与不可破坏约束

### 4.1 状态定义

- 授权：`ACTIVE / PAUSED / REVOKED / EXPIRED`。
- 计划：`DRAFT -> SCHEDULED -> RUNNING -> COMPLETED`，异常终态为 `ABORTED / FAILED / CANCELLED`。
- 会话：`OFFERED -> ACCEPTED -> DISCHARGING -> SETTLING -> SETTLED`，拒绝、超时或撤销进入 `CANCELLED`，安全异常进入 `ABORTED`。
- 设备方向：`IMPORT / EXPORT / IDLE`；`powerW` 始终为非负绝对值，禁止同时用正负号和方向字段表达两套含义。
- 普通订单不得增加任何 V2G 状态。电桩继续使用项目统一枚举，不新增 `DISCHARGING` 等字符串。

### 4.2 不变量

1. 功能开关关闭时，不生成邀请、不发送双向命令、不展示为正式能力。
2. 同一站点同一时间最多存在一个 `RUNNING` 的 MVP V2G 计划；同一虚拟车辆最多存在一个活动能量传输会话。
3. V2G 会话与普通 `RESERVED / CHARGING / PENDING_PAYMENT` 订单资源互斥；活跃 V2G 资源不得出现在可预约空闲桩列表。
4. 不为 V2G 创建伪造普通充电订单，不向普通订单状态增加 V2G 字符串。
5. 输出后 SOC 不得低于用户授权版本中的最低保留 SOC；每个时间片都必须基于实际输出 Wh 重算。
6. 用户未接受、授权过期/撤销、设备离线、心跳或遥测过期、达到 SOC 下限时，目标输出必须为 0，并执行安全终止。
7. ACK 只表示收到命令；只有匹配会话的结果和遥测才能累计实际输出。
8. 模型和模拟器不得写订单、钱包、支付和正式营收。模拟补偿只能写独立实验账本，并以唯一业务键防止重复。
9. 服务重启后，对无法证明仍安全的会话默认终止；设备重连时首先同步为 `IDLE/0W`，不能自动恢复反向输出。
10. 页面、日志、报告和演示材料都必须显示“纯模拟、未真实并网、不可作为收益承诺”。

资源占用应通过独立 V2G 会话锁与可用性查询实现。若现有电桩服务必须使用统一状态表达占用，可由服务端临时使用合法的 `RESERVED` 并配合 `power_direction=EXPORT`，结束后恢复；不得由模拟器自行改状态，也不得发明新的电桩状态。

## 5 建议实现设计

### 5.0 技术路线校准（对齐真实仓库）

| 原文档设计 | **校准后落地** | 为什么 |
| --- | --- | --- |
| SOC 用基点 `0..10000` | **整数百分比 `0..100`** | 见 00 第 4.5 节；本项目无需万分之一精度 |
| 功率 `powerW` 整数 W | **kW（`REAL`）**，与 `t_pile.power`、`t_energy_policy.capacity_kw` 一致 | 同上；本模块必须与 06 的容量模型同单位，否则两边算不到一起 |
| 能量 Wh | **`kwh_x100`**（度 × 100 的整数） | 同上 |
| `reward_minor_per_kwh`「模拟最小单位」 | **模拟补偿一律用「分」计价并明确标注为模拟值**：`reward_fen = round(export_kwh_x100 × rate_fen_per_kwh / 100)` | 再造一种「模拟货币单位」只会让人看不懂账本；用分并靠**表与查询入口的物理隔离**保证不混入正式营收 |
| 与正式钱包隔离 | **强化为硬性要求**：`t_v2g_ledger` 与 `t_wallet_tx` 物理分离，且 `statistics_service.cpp` 的 2301/2302、`ml/export_snapshot.py` 的营收口径**均不得包含本表**。认领人必须在 DoD 里逐项验证 | 一旦混入，管理端营收与大屏数字会当场对不上，且很难查 |
| `SET_BIDIRECTIONAL_POWER` 等设备动作名 | **设备段 `9050–9079` 的数字命令字**，沿用已冻结信封；`V2G_CAPABILITY_REPORT`、`V2G_TELEMETRY` 同理 | 见 00 第 4.2 节 |
| 双向能力与 SOC 来源 | **由模拟器提供**：`tools/pile-simulator/` 增加虚拟车辆档案（容量、SOC、最大输入/输出功率、双向能力），固定随机种子保证演示可复现 | 项目没有真实车辆；车辆档案表 `t_v2g_vehicle` 只是服务端侧的镜像 |
| 与普通充电资源互斥 | 判定沿用 00 第 4.5.1 节：该桩**无活动订单**（`t_order.status IN (0,1,2)`）且 `t_pile.status = 1(闲置)` 且 `online = 1`。**活跃 V2G 会话期间该桩不得出现在 1101/1102 的可预约列表中** | 电桩仍只有三态；V2G 占用同样靠独立表判定，不加第四个状态值 |
| Python 优化器 | **不引入**，与 06 一致：C++ 确定性削峰算法 | 任务卡非目标 |

**安全约束（本模块的核心验收点）**：每个调度时间片都必须重新校验 SOC 下限、授权有效性、心跳新鲜度与离场时间，任一不满足**立即把目标功率归零**。SOC 只依据**经过校验的实际输出电量**更新，**不得依据计划功率或命令 ACK 预扣**。

**命令字段**：`3900–3939` 用户端（授权/暂停/撤销、邀请查询与接受/拒绝、会话查询）、`3940–3979` 管理端（实验开关、计划预览/批准、人工终止、会话查询）、设备段 `9050–9079`（能力上报、双向功率下发、V2G 遥测）。

**错误码登记表**：`6901 ERR_V2G_DISABLED`（实验未开启）、`6902 ERR_V2G_NOT_ENROLLED`、`6903 ERR_V2G_SOC_LOW`、`6904 ERR_V2G_OFFER_EXPIRED`、`6905 ERR_V2G_BUSY`（该桩有普通活动订单）。

**建表脚本 `docs/db-schema-ext-10.sql`**：`t_v2g_config`、`t_v2g_vehicle`（`capacity_kwh_x100, soc_pct, min_soc_pct, max_in_kw REAL, max_out_kw REAL, bidirectional`）、`t_v2g_enroll`、`t_v2g_plan`、`t_v2g_alloc`、`t_v2g_session`、`t_v2g_sample`、`t_v2g_ledger`（`session_id UNIQUE, export_kwh_x100, rate_fen_per_kwh, reward_fen, req_id UNIQUE, create_time`）。**全部表名带 `t_v2g_` 前缀**，便于在营收 SQL 里一眼确认没有被误引用。

### 5.1 架构

以下名称仅描述职责，实施前必须映射到仓库真实结构：

- `V2GFeatureGate`：全局/站点实验开关和权限校验。
- `V2GEnrollmentService`：授权、暂停、撤销、过期和版本管理。
- `V2GEligibilityService`：双向能力、SOC、新鲜度、离场时间和普通订单互斥检查。
- `BaselineV2GPlanner`：纯函数确定性削峰算法，只输出候选计划。
- `V2GDispatchService`：计划、邀请、接受、再次校验、会话状态和审计。
- `BidirectionalCommandAdapter`：复用设备命令服务发送双向功率，不另建旁路控制通道。
- `V2GSafetyMonitor`：每个时间片检查 SOC、授权、心跳、遥测和时间条件，并执行归零。
- `V2GSimulationLedgerService`：按实际输出 Wh 生成唯一模拟补偿，不调用正式钱包服务。
- `V2GQueryService`：为用户端、管理端和 Web 返回带实验标识的数据。

V2G 代码、表、接口和统计命名应带明确实验前缀/字段，避免被正式订单、钱包或财务聚合误读。计划和会话状态在短事务中提交，不能持有事务等待用户或设备网络响应。

### 5.2 数据

| 实体 | 必要字段 |
|---|---|
| `v2g_experiment_config` | 功能开关、站点、阈值 W、最大实验功率 W、邀请超时、模拟补偿单价、版本 |
| `v2g_vehicle_profile` | 虚拟车辆、用户、容量 Wh、SOC 基点、最低/最高 SOC、最大输入/输出功率、双向能力、版本 |
| `v2g_enrollment` | 用户/车辆、状态、最低保留 SOC、预计离场、有效期、同意版本、更新时间/版本 |
| `v2g_dispatch_plan` | 站点、目标削峰 W、时间窗、状态、算法/配置版本、输入截止时间、幂等键 |
| `v2g_allocation` | 计划、车辆、目标功率 W、最大可用 Wh、分配理由、命令编号、执行状态 |
| `v2g_session` | 会话、计划、车辆、状态、接受/开始/结束时间、最终输出 Wh、终止原因、授权版本 |
| `v2g_meter_sample` | 会话、采样时间、方向、功率 W、累计输入/输出 Wh、SOC 基点、质量标记、序号 |
| `v2g_simulation_ledger` | 唯一业务键、会话、实际输出 Wh、模拟单价、模拟补偿最小单位、创建时间、冲正关联 |

模拟补偿单价建议使用“每 kWh 的整数模拟最小单位”，例如 `reward_minor_per_kwh`；计算为 `round_half_up(actual_export_wh * rate / 1000)`。账本必须与正式钱包流水使用不同表/类型和查询入口，正式营收 SQL 应显式排除实验数据。

### 5.3 方向、功率和 SOC 约定

- `IMPORT`：能量从站点流向车辆；`EXPORT`：能量从车辆流向站点的纯模拟；`IDLE`：目标功率为 0。
- `powerW` 始终为非负整数。站点模拟净输入功率为：`other_load_w + charging_import_w - v2g_export_w`。
- SOC 使用基点 `0..10000`；能量使用整数 Wh。
- 单时间片可输出能量受以下最小值约束：设备最大输出、站点目标、实验配置上限、离场前可执行时长、最低保留 SOC 上方的可用能量。
- 可用能量：`max(0, floor(capacity_wh * (soc_bps - reserve_soc_bps) / 10000) - safety_buffer_wh)`。
- SOC 只依据经过校验的实际输出 Wh 更新，不依据计划功率或 ACK 预扣。

### 5.4 MVP 调度算法

1. 计算 `target_shave_w = max(0, predicted_or_actual_net_import_w - experiment_threshold_w)`。
2. 过滤未授权、用户未在线同意（如方案要求）、非双向、设备离线、遥测过期、离场时间已到、有普通活动订单或可用能量为 0 的车辆。
3. MVP 只选择固定演示车辆；若有多个候选，按可用能量降序、离场时间升序、车辆 ID 稳定排序。
4. 计算 `target_export_w = min(target_shave_w, vehicle_max_export_w, station_experiment_cap_w, energy_limited_power_w)`。
5. 保存计划并发出限时邀请。用户接受后重新计算一次，结果可能因 SOC/负荷变化而降低，绝不能提高到超出已展示上限。
6. 通过设备命令服务下发 `SET_BIDIRECTIONAL_POWER`，周期读取实际输出并决定继续或归零。

Python 优化器仅作为后续增强；它只能返回候选分配，并必须经过同样的服务端约束校验和 C++ 安全回退。

### 5.5 协议和 UI

可在统一协议中增加或复用：

- 设备侧：`V2G_CAPABILITY_REPORT`、`SET_BIDIRECTIONAL_POWER`、`V2G_TELEMETRY`、`COMMAND_ACK`、`COMMAND_RESULT`。
- 用户侧：`V2G_ENROLL / V2G_PAUSE / V2G_REVOKE`、`DISPATCH_OFFER_QUERY / DISPATCH_ACCEPT / DISPATCH_DECLINE`。
- 管理侧：`V2G_PLAN_PREVIEW / V2G_PLAN_APPROVE / V2G_DISPATCH_ABORT / V2G_SESSION_QUERY`。

用户端最小页面显示实验徽标、授权条件、邀请倒计时、当前 SOC、最低 SOC、实际输出和模拟补偿，并提供随时撤销。管理端显示功能开关、负荷曲线、计划、参与资源、命令/安全时间线和人工终止。Web 图表显示调度前后负荷、目标/实际输出、SOC 和模拟补偿，数据不得并入正式营收卡片。

## 6 顺序实施步骤

| 步骤 | 实施内容 | 本步产出 | 完成验证 |
|---|---|---|---|
| 1 | 盘点仓库的设备双向能力、SOC 遥测、能源快照、用户会话、资源互斥、钱包/营收查询和测试入口 | 短计划、真实路径映射、隔离风险清单 | 能明确实验数据如何与订单、钱包、营收隔离；无臆造路径 |
| 2 | 冻结“纯模拟”文案、功能开关、方向/单位、状态、SOC 公式和固定一站一车数据 | 领域约定与手算夹具 | 手算一次 10～30 分钟输出后的 SOC、Wh、峰值和模拟补偿 |
| 3 | 增加实验配置、车辆、授权、计划、会话、表计和独立模拟账本迁移 | 可重复数据层 | 空库可初始化；活动会话、账本业务键和授权版本约束生效 |
| 4 | 实现授权/暂停/撤销和 eligibility 纯校验 | 授权服务与测试 | 未授权、过期、SOC 不足、有普通订单或设备离线均不可入选 |
| 5 | 实现纯函数单车削峰计划，不连接设备 | 计划预览 | 固定输入输出确定；目标功率不越任何上限；不改订单/钱包 |
| 6 | 实现邀请、接受、超时和接受前再次校验 | 用户交互闭环 | 未接受不下发功率；重复接受幂等；授权变化后旧邀请失效 |
| 7 | 接入双向设备命令和方向明确的模拟遥测 | 单车反向输出闭环 | ACK 不累计电量；只有实际输出 Wh 更新会话和 SOC |
| 8 | 实现 SafetyMonitor、归零、异常终止和重启恢复 | 安全闭环 | 达到 SOC 下限、撤销、掉线、遥测过期和重启均停止输出；先归零再释放资源 |
| 9 | 实现独立模拟补偿账本和正式统计隔离 | 一次性模拟结算 | 重复最终遥测/重复请求只生成一笔账；正式钱包及营收完全不变 |
| 10 | 完成用户端/管理端最小页面、曲线、免责声明、演示脚本和全量测试 | 可验收 MVP | 一站一车演示可重复；所有页面均显示纯模拟；关闭开关后无实验动作 |

多车辆分配、分时电价、碳强度和 Python 优化只在上述 MVP 完成后逐项追加，每次仍需保持正式业务隔离。

## 7 测试矩阵

| 层级 | 场景 | 关键断言 |
|---|---|---|
| 单元 | SOC/Wh 换算、时间片积分、整数舍入 | 结果可手算，无浮点漂移，SOC 不越 `0..10000` |
| 单元 | 目标低于/高于阈值，各类功率上限 | 目标输出为正确最小值，站点模拟净负荷公式正确 |

| 单元 | eligibility 各拒绝条件 | 未授权、过期、离线、遥测过期、普通订单冲突均有明确原因 |
| 集成 | 功能开关关闭 | 无邀请、无命令、无账本，普通业务不受影响 |
| 集成 | 邀请接受/拒绝/超时/重复接受 | 仅首次合法接受生效；其他请求幂等或明确拒绝 |
| 集成 | 接受前 SOC、授权或普通订单变化 | 旧计划失效，不下发输出命令 |
| 集成 | ACK 成功但无结果/遥测 | 不累计输出、不生成模拟补偿，并按超时安全终止 |
| 集成 | 正常输出到峰值结束 | 实际输出 Wh 单调，站点模拟峰值下降，最终归零 |
| 集成 | 到达最低 SOC | 不低于授权下限，发送 0W 并终止 |
| 集成 | 用户撤销、设备掉线、遥测过期 | 在安全周期内归零/中止，不继续累计 |

## 8 Definition of Done

- [ ] V2G 默认关闭，只有开启实验开关并满足权限/授权后才可创建计划。
- [ ] 固定一站一车数据可完整演示授权、邀请、接受、反向输出、归零和一次模拟补偿。
- [ ] 模拟器、调度器和模型没有直接修改普通订单、正式钱包、支付和正式营收的路径。
- [ ] 模拟补偿位于独立实验账本，重复事件不会重复记录，正式财务统计明确排除。
- [ ] 功率方向和单位唯一明确，SOC 根据实际 Wh 更新且永不低于授权最低值。
- [ ] V2G 与普通预约/充电资源互斥，无伪造普通订单和新增订单状态字符串。
- [ ] 撤销、超时、离线、遥测过期、SOC 下限和服务重启都能安全归零或明确终止。
- [ ] 用户端、管理端、Web 和演示文档持续显示“纯模拟、未真实并网、不可作为收益承诺”。
- [ ] 测试矩阵核心场景通过；未运行或失败测试有真实命令、原因与剩余风险。
- [ ] 运行说明包含固定种子、启动顺序、功能开关、手算预期、演示步骤、恢复方式和非目标。

## 9 风险与降级方案

| 风险 | 识别信号 | 降级方案 |
|---|---|---|
| 被误解为真实 V2G | 页面出现“并网成功”“实际收益”等文案 | 所有入口增加实验徽标和免责声明；统一改为“模拟输出/模拟补偿” |
| 前置设备双向能力不稳定 | 无 SOC、新鲜度或可靠 0W 命令 | 降级为离线曲线仿真，不下发任何设备命令，不显示为已执行 |
| 与普通订单资源冲突 | 同一桩可同时预约和 V2G | 暂停在线实验，先实现服务端唯一资源锁和可用性过滤 |
| 安全恢复复杂 | 重启后无法确认是否仍在输出 | 一律标记 `ABORTED`，重连先发送 `IDLE/0W`，不自动续跑 |
| 正式钱包污染 | 复用钱包流水导致余额变化 | 删除该接线，使用独立模拟账本；若无法隔离则只展示会话结果不生成补偿 |
| 多车调度范围失控 | 提前引入优化器、公平性和多站点 | MVP 锁定一站一车确定性算法，多车仅作为后续任务 |
| 演示数据不稳定 | 每次随机负荷、SOC 和收益不同 | 固定随机种子和时间轴，保留手算基准及期望输出 |
