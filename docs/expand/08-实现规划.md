## 2 冻结口径

开发中不得再改；要改先改本节，并同步 08 文档的命令字登记表。

**单位**（00 §4.5）：电量 `kwh_x100` 整数；因子 `factor_g_per_kwh` 整数克/度；排放 `emission_g` 整数克；
强度 `intensity_g_per_kwh` 整数克/度；完整度与估算占比整数 0..100，**总量为 0 时一律 `-1` 表示「不适用」**，不伪装成 100。

**算式**（全整数，四舍五入用 `+除数/2` 而非浮点）：

```
emission_g          = (kwh_x100 * factor_g_per_kwh + 50) / 100
intensity_g_per_kwh = (emission_g * 100 + total_kwh_x100 / 2) / total_kwh_x100     // total=0 → -1
completeness        = (100 * (total_kwh_x100 - unalloc_kwh_x100) + total/2) / total // total=0 → -1
```

中间值一律 `qint64`：实测全量 `kwh_x100` 合计 36,638,035，乘 581 约 2.1×10^10，**32 位必溢出**。

**分时切分**（守恒，最大余数法）：单笔订单按 `[start_time, end_time)` 与三类时段的**重叠秒数** `d_peak/d_flat/d_valley` 分摊：
`raw_i = kwh_x100 * d_i / D` 整除，余数最大者优先领取 `kwh_x100 - Σraw_i` 的剩余单位，
并列时固定顺序 峰 > 平 > 谷。**保证 `peak + flat + valley + unalloc ≡ total`，逐单成立，聚合后也成立。**

**固定时段** `[本组自定]`，模块 05 未做时的降级口径，页面与导出**必须标注「固定时段口径」**：

| 段 | 区间（左闭右开，本地时间） | 时长 |
| --- | --- | --- |
| 峰 | `10:00–15:00`、`18:00–21:00` | 8h |
| 平 | `07:00–10:00`、`15:00–18:00`、`21:00–23:00` | 8h |
| 谷 | `23:00–07:00` | 8h |

**演示因子**：`581 g/kWh`，region `全国电网平均`，version `demo-2022`，
source「生态环境部 2022 年全国电网平均二氧化碳排放因子 0.5810 tCO2/MWh，**课程项目演示用，非认证数据**」，
`effect_from = '2000-01-01 00:00:00'`，`effect_to = NULL`（右开无穷）。生效区间**左闭右开**，重叠由服务端在 3742 拒绝。

**数据质量**：`t_order` 无表计区间数据，MVP 中 `METER_INTERVAL` **永不出现**（列保留，文档注明未使用）。
`start_time`/`end_time`/`kwh_x100` 齐全且 `end > start` → `UNIFORM_ESTIMATE`；否则 → `UNAVAILABLE`，
该单电量整体计入 `unalloc_kwh_x100` 并拉低完整度。实测当前 6477 单**零缺失**，因此完整度恒为 100 ——
夹具库里必须**人为造缺失单**，否则降级路径根本没被验过。

**免责声明**（页眉、导出文件头、快照 JSON 三处同一份字符串）：
`课程项目估算，非认证碳数据，不可用于碳交易或监管申报`。

## 3 数据模型 · `docs/db-schema-ext-08.sql`

只允许 `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS` / `INSERT OR IGNORE`（00 §4.4），**幂等，可重复执行**。

| 表 | 关键列 | 约束 |
| --- | --- | --- |
| `t_carbon_factor` | `factor_id` PK, `region`, `effect_from`, `effect_to`, `factor_g_per_kwh` INTEGER, `source`, `version`, `enabled`, `create_time` | `UNIQUE(region, version)`；区间重叠由服务端校验（SQLite 表约束表达不了区间重叠） |
| `t_carbon_daily` | `station_id`, `stat_date`, `total_kwh_x100`, `peak/flat/valley/unalloc_kwh_x100`, `order_cnt`, `emission_g`, `intensity_g_per_kwh`, `completeness`, `estimated_pct`, `quality`, `factor_version`, `algo_version`, `cutoff_time`, `update_time` | **`UNIQUE(station_id, stat_date, factor_version, algo_version)`** + `INSERT OR REPLACE` = 幂等重算 |
| `t_carbon_report` | `report_id` PK, `scope`, `station_id`, `date_from`, `date_to`, `version`, `status`, `run_time`, `cutoff_time`, `factor_version`, `algo_version`, 指标快照列, `output_path`, `req_id` | `UNIQUE(req_id)`（00 §4.6 幂等）；`status ∈ GENERATING/READY/FAILED/STALE` |

`carbon_peak_ranges`、`carbon_valley_ranges`（平段 = 24h 扣掉峰谷，不单独配，杜绝三者配不满 24 小时）。

## 5 服务端设计

`server/biz/ext_08_carbon_calc.{h,cpp}` —— **纯函数、零数据库依赖**：时段切分、最大余数分摊、
因子选择、整数排放与强度。所有手算夹具打在这一层。

`server/biz/ext_08_carbon_service.cpp` —— 导出 `registerExt08CarbonService()`，7 个 handler。

- **只读** `t_order` / `t_station`，**只写** `t_carbon_*`。全文件 `grep` 不得出现对
  `t_user` / `t_wallet_tx` / `t_pile` / `t_order` 的 `UPDATE`/`INSERT`/`DELETE`。
- 连接一律 `ecp::threadDb()`；SQL 一律 `prepare` + `addBindValue`。
- **不持长事务**：先定 `cutoff_time = 本次开始时刻`，再**按日**读取、计算、短事务写入。
- **懒聚合**：3740 对范围内每一天比对 `t_carbon_daily.order_cnt` 与
  `SELECT COUNT(*) FROM t_order WHERE status=3 AND date(settle_time)=?`，不一致（含无行）则重算该日。
  今日永远重算。重算后若某 `READY` 报告覆盖该日且数字变了 → 该报告置 `STALE`（不覆盖旧数字）。
- **并发**：同范围两个请求同时重算，靠 `UNIQUE` + `INSERT OR REPLACE` 收敛为同一结果，不加额外锁。
- **导出**：写到 `export/carbon/report_<id>_v<n>.{csv,html}`，返回相对路径。
  假设管理端与服务端同机（演示场景），**须在页面上写明**。

## 6 管理端设计

`admin-client/ext_08_carbon_page.{h,cpp}`，导航项「碳排放报告」，照 `overview_page` 的
`NetClient::send` + `response` 信号范式，**不新增线程**（硬性规则 4）。

指标卡（总电量 / 估算排放 / 排放强度 / 完整度）、峰平谷构成、排放趋势（`HAVE_CHARTS` 未定义时降级为表格，
与 `overview_page` 一致）、因子版本选择、报告生成与导出、`STALE` 角标。

**开关关闭时**：handler 未注册 → 返回 `ERR_CMD_UNKNOWN(1005)` → 页面显示「该功能未启用」。
不新增「查询开关」命令字（那要动核心），符合 00 §4.7「拿不到开关状态时按关闭处理」。
