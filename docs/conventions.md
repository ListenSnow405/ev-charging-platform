### 依赖安装

基础环境（全员）：

```bash
sudo apt install qt6-base-dev qt6-base-dev-tools qmake6 g++ sqlite3
```

⚠️ **`QtCharts` 与 `QtWebEngineWidgets` 不在 `qt6-base-dev` 里，需要单独装。** 这两个正是说明书明文要求的功能所依赖的模块，缺了 L3 和 L4 直接无法开工：

```bash
# L3 需要 —— [说明书] 1.4 营收趋势折线图使用 QChart 组件
sudo apt install libqt6charts6-dev

# L4 需要 —— [说明书] 1.4 一键导航使用 QWebEngineView 加载腾讯地图
sudo apt install qt6-webengine-dev qt6-webengine-dev-tools
```

两个包在 Ubuntu 22.04 上均为 **6.2.4**，与基础 Qt 版本一致，不会冲突。

### 验证：`scripts/check-env.sh`

**全员在 W1 第一天跑一次，把「结论」一行贴到群里。**

```bash
bash scripts/check-env.sh        # 检查全部模块
bash scripts/check-env.sh L3     # 只检查自己这条线需要的
```

脚本会依次检查基础工具、Qt 版本是否为 6.2.4、各模块头文件、QSQLite 驱动，并对 QtCharts / QtWebEngineWidgets **实际做一次试编译**；未通过时直接打印该装哪些包。退出码等于未通过项数，可用于脚本判断。

> **为什么要试编译而不是只看包名**：这两个模块各有「运行库」与「开发包」两个 deb。`libqt6charts6` 是运行库，`libqt6charts6-dev` 才带头文件。若因其他软件的依赖装上了运行库，`dpkg -l | grep charts` 能看到东西，容易误判为已装好，但编译时仍会报找不到头文件。**试编译是唯一可靠的判定。**

这是 agent 完全帮不上忙的环境问题，拖到联调周才发现会连累全组。

## 6. 配置与密钥管理

`[说明书]` 2.2：合理考虑数据安全问题。

### 6.1 规则

**任何凭据都不进仓库。** 本地配置文件 `config/app.ini` 已被 `.gitignore` 忽略；仓库里只保留模板 `config/app.ini.example`。

```bash
cp config/app.ini.example config/app.ini   # 首次克隆后执行，然后填入自己的值
```

模板改了要提交，实际配置永远不提交。已验证：`git add config/` 只会加入 `.example`，`app.ini` 不会被跟踪。

### 6.2 腾讯地图 Key 说明

`[说明书]` 1.4 两处功能依赖腾讯地图 Web API：**地址转经纬度**（附近充电站查询）与**路线规划**（一键导航）。调用这两个接口必须带一个 Key。

**Key 是什么** —— 腾讯位置服务（lbs.qq.com）给开发者账号发的一串调用凭据，绑定在申请人的微信/QQ 账号上，**按 Key 计算免费额度**（地理编码约 1 万次/日）。

**为什么要单独管理，有三个理由：**

1. **额度是共享的。** 五个人共用一个 Key，联调时反复调地理编码，很容易在同一天把额度跑满。跑满之后接口直接返回配额错误——如果这天正好是答辩，导航功能当场演示不了。所以**每人各申请一个**，互不影响。

2. **Key 进了 git 就撤不干净。** 即使后来删掉，它仍留在提交历史里。仓库如果要提交给老师、推到 GitHub 或者在答辩时投屏 `git log`，Key 就暴露了。别人拿到可以直接消耗你的额度，腾讯检测到异常调用还可能封禁这个 Key。

3. **它是说明书 2.2「数据安全」的一个具体落点。** 答辩时被问「你们怎么考虑数据安全的」，除了密码存 SHA-256、SQL 参数绑定，凭据不入库也是一条能讲的实事。

**申请步骤**（L4 负责整理并在群里同步给需要的人）：

1. 访问 <https://lbs.qq.com/>，用微信或 QQ 注册开发者账号，完成实名认证
2. 控制台 → 应用管理 → 我的应用 → **创建应用**
3. 在应用下**添加 Key**，产品类型勾选 **WebServiceAPI**（地址解析用）与 **JavaScript API**（网页导航用）
4. 配置授权：本机调试可将 IP 白名单留空或填 `0.0.0.0/0`；**答辩演示机的出口 IP 要提前加进去**
5. 复制 Key，填入本地 `config/app.ini` 的 `[map] key=` 后面

**代码里怎么用** —— 从 `config/app.ini` 读，禁止硬编码：

```cpp
QSettings cfg("config/app.ini", QSettings::IniFormat);
const QString mapKey = cfg.value("map/key").toString();
if (mapKey.isEmpty()) {
    LOG_E("地图 Key 未配置，请复制 config/app.ini.example 为 config/app.ini 并填入 Key");
    // 提示用户而不是静默失败 —— [说明书] 2.3 完整的错误处理机制
}
```

> **给 agent 的提示**：生成涉及地图调用的代码时，Key 一律从 `config/app.ini` 读取。**任何情况下都不要把 Key 字面量写进 `.cpp`、`.h`、`.pro` 或提交信息里**，也不要在示例代码里编造一个假 Key 占位。

## 7. 分支与提交规范 `[本组自定]`

- **分支**：`main` 为集成分支。各线在 `feat/L1-xxx`、`feat/L3-xxx` 形式的分支上开发，自测通过后合入 `main`。
- **合入前**：确认只改了自己归属目录下的文件（CLAUDE.md 第 4 节）。
- **提交粒度**：按功能点小步提交。**禁止一次提交上千行**——评分要看过程贡献，一次巨大提交既难评审也体现不出过程。
- **提交信息**：写人话，说清这次解决了什么问题。

  ```
  ✅ feat(L2): 订单结算扣减钱包余额，余额不足返回 ERR_BALANCE_NOT_ENOUGH
  ✅ fix(L1): 修正半包场景下长度头未读满即解析的问题
  ❌ 完成管理端
  ❌ update
  ```

- **禁止提交**：`config/app.ini`、`*.db`、构建产物、`.pro.user`（均已在 `.gitignore` 中）。
- **推送**：由本人确认后手动推送，不要让 agent 直接执行 `git push`。
